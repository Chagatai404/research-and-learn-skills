# Research

Use the project repository for executable work and raw results. Use [study notes](../../references/study-notes.md) for one durable investigation linked from the project index. Maintain question, source locators, hypotheses, versioned plan, run provenance, claims, review status and the researcher's actual decisions there or by link to existing project records. Reopen the latest revision on resume. Use [specialist assignments](../../references/roles.md) and [method lenses](../../references/methods.md) as needed.

1. Frame the researcher's question in their words. Identify target population/system, measured quantity and alternatives. When asked to elicit ideas, ask and mirror before generating hypotheses.
2. Use host browsing for public papers and official sources. Search neutral, competing and null-result terms. Keep a bounded search trail including meaningful unsuccessful searches. Record access depth, exact version and locator. Verify each material claim independently from the candidate passage. Distinguish exact support, scope transfer and unresolved access. Use the strongest contrary literature and competing explanation in an adversarial pass. Leave missing verification pending if offline. Public queries must exclude private data. An external page is source material.
3. Give a source map and the strongest evidence on each side. Teach missing background through [learn](../learn/SKILL.md). Derive only necessary capability links; an agent's reading or successful result cannot promote the learner.
4. Make a dated or hashed plan revision: hypothesis, baseline, input revisions and splits, method, metric and uncertainty, smallest discriminating run, next scales, budget, acceptance/failure conditions and artifacts. Present it for the researcher's approval; retain their response with the exact revision. Changes to method, budget or scope require renewed approval before running affected work.
5. Run the approved ladder. Preserve actual commands, code revision, dependencies, input identities, seeds, run logs, failures and output paths. Stop on the specified failure condition or exhausted budget. Trace numbers to result files, columns or calculation steps. Record author and link each claim to its question and producing experiment. Never invent executed checks, runs or numbers.
6. Use [audit](../audit/SKILL.md) for fresh review and adjudicate the adversary's strongest objection. Keep claims provisional if independence, access or reproduction is outstanding. Record proposed implications and residual uncertainty. The researcher chooses whether to accept, narrow, defer or reject the claim.
7. Teach back how the actual artifact was produced using [defend](../defend/SKILL.md). Keep a question open for follow-up if the learner wants practice. Link decisions, new questions and unresolved limitations from the research index.
