# Teaching in the vault

Resolve the vault the learner selected. Search the relevant course or project index for titles, aliases and section links. A course index maps every syllabus week and objective to its week note and topic heading, including future objectives marked as uncovered. Group by the documented syllabus. Keep material with uncertain dates in a clearly linked unassigned section until alignment is established. For independent study, extend the coherent subject note. For research, link each sustained question from the project overview. Use existing source notes, attachments and mathematical notation.

A week opens with previous/index/next links, goals, a short gist and a retrieval prompt. Under each topic give the full explanation, a worked example or derivation, assumptions and a precise source locator. Keep practice at the topic it tests. For a concrete open prompt use a heading such as “Practice · Product states”, the question and an empty **My answer** field. Explain that the learner can answer in chat or edit that field and say “ready”. Re-read the field on submission. Editing the note alone does not wake an assistant. Do not include the rubric, worked solution to the same item or a prefilled learner answer before submission. On return, check for an active prompt before creating another.

Retain meaningful original reasoning verbatim, including mistakes, followed by compact correction and a useful next example. Store repetitive attempts in the learner profile. Give permanent notes headings and links that remain useful after the semester. Preserve the distinction between an instructor's explanation, an agent's interpretation and the learner's words. Keep session bookkeeping, hidden grading materials and database keys outside the note.

Before writing, resolve the intended file within the selected root, inspect the existing section, check its latest revision and patch only that section. Re-read the edited text. Preserve concurrent human edits, block IDs, heading links and embeds. For bulk moves or replacements stage a manifest and backups, check all destinations and links, exercise restoration on a copy and verify each applied batch. Leave conflicts open for reconciliation. Keep credentials and private environment values out of the vault.

For ordinary changes save the proposed full text to a draft outside the vault. From the plugin root run `python scripts/note_edit.py preview VAULT RELATIVE_NOTE DRAFT`, inspect the diff and both digests, then run `python scripts/note_edit.py apply VAULT RELATIVE_NOTE DRAFT --expect ORIGINAL_DIGEST --draft-hash PROPOSED_DIGEST`. On conflict re-read the human's latest edit and prepare a new draft. Use the helper's help for supported paths and creation behavior.
